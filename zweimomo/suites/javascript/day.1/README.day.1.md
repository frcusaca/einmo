# day.1 — the absolute basics

This is the first tier a new einmo user (or a fresh contributor to this
repo) sees. It answers one question: **does einmo work, end to end, on the
simplest realistic content?**

## What's here

Eight `.js` inputs, ported from `foolish-rust`'s original three-language
`zweimomo` crate (the JavaScript column only — see `EIMP-2` §8 in
`docs/eimp/`):

| Input | Concept |
|---|---|
| `integer_arithmetic.js` | operator precedence |
| `nested_expressions.js` | parenthesized/nested expressions |
| `name_binding.js` | `let`/variable binding and reference |
| `data_structures.js` | object literals and property access |
| `function_application.js` | function definition and call |
| `division_by_zero.js` | JS's `Infinity` value (not an error — contrast with Python's `ZeroDivisionError` in the original three-language corpus) |
| `search_query.js` | property lookup by key |
| `nested_expressions++divisionByZero.js` | a dependent-pair input (the `++` naming convention — see `EIMP-1`'s DIFF section) |

Each has a signed `output/` artifact (generated by `BoaEvaluator`) and a
matching human-reviewed `checked/` baseline, signed under this tier's
configured `checked`-stage passphrase (`einmo.toml` in this directory — see
the crate root [`README.md`](../../../../README.md#signing-configuration)).

## Try it yourself

```bash
cd zweimomo
cargo test javascript_tiers_generate_and_verify
```

This evaluates every input in every populated tier (today, just `day.1/`)
and asserts the output matches the reviewed `checked/` baseline
byte-for-byte.

To review a change to `BoaEvaluator` or to one of these inputs by hand:

```bash
cargo run -p einmo --bin einmo -- list suites/javascript/day.1
cargo run -p einmo --bin einmo -- compare output checked suites/javascript/day.1
```
